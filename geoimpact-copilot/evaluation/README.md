# GeoImpact Evidence Copilot evaluation (V0.2)

SPDX-License-Identifier: CC0-1.0

Everything here is offline and deterministic. **All scores describe software behaviour on invented, schema-valid reports. They are not measurements of scientific accuracy on real GeoImpact-CI output.**

## Layers

| Layer | Where | What it proves | What it cannot prove |
| --- | --- | --- | --- |
| Deterministic unit tests | `tests/geoimpact-copilot.test.mjs`, `tests/geoimpact-semantic.test.mjs` | Specific behaviours and regressions on committed fixtures | Anything about reports not tried |
| Independent expected answers | `expected-answers.json` | Hand-typed expectations on committed fixtures match the output | Correctness beyond those exact strings |
| Generated oracle | `oracle.mjs` + `synthetic/generator.mjs` | Answers on seeded reports match expectations stated from the generator's spec, not from the code under test | Real-world report diversity |
| Adversarial mutations | `mutations.mjs` | The gate rejects meaning-changing edits whose numbers, identifiers and citations are individually valid | Attacks nobody thought to write |
| Input-boundary, injection and Unicode cases | `run-v2.mjs` | Malformed or hostile reports are rejected or treated as data | Unknown parser differentials |
| Performance | `run-v2.mjs --perf-one` | Time and memory at three sizes on one machine | Hardware-independent limits |

`npm run evaluate:copilot:v2` runs all of them and exits non-zero if any gate fails. The older `npm run evaluate:copilot` (27 V0.1 regression cases) still runs unchanged.

## Splits

`synthetic/manifest.json` fixes two seed ranges and records a SHA-256 over each split's generated bytes, so a changed generator or seed is detected.

* **development**: every seed that was inspected or used while writing the gate, the generator and the sentence vocabulary. It includes the first held-out draft, whose failures drove fixes and which was therefore folded in.
* **held_out**: drawn after those fixes. The sentence vocabulary was built without it. **If a held-out failure ever drives a code change, move those seeds into development and draw new ones.**

Both splits come from one author and one generator, so "held-out" here is procedural. It limits overfitting to inspected cases; it is not independent validation.

## External, rights-cleared reports

No real report is bundled, and none is required. To evaluate reports you are entitled to use:

1. Put `NAME.report.json` and `NAME.meta.json` in a directory outside this repository (or a git-ignored one).
2. `NAME.meta.json` must satisfy `external/metadata.schema.json`: source provenance, dataset rights with evidence URL, `redistribution_allowed: true`, `contains_personal_data: false`, the report's SHA-256, a development/held-out assignment, independent labels with who labelled them, a human-review status, and uncertainty notes.
3. `npm run evaluate:copilot:v2 -- --external DIR`.

A report with missing rights, a hash mismatch or no labels is rejected and fails the gate. Reports whose review status is not `reviewed` are listed separately and **never enter an aggregate**.

## Reading the numbers

* `rejected_by_reference_verifier` is the current citation/typed-literal/numeric verifier with the semantic gate disabled. It is not the historical V0.1 executable.
* Rates carry n and a Wilson 95% interval. A rate of 1.0 means no failure in n cases; the lower bound shows how little that establishes.
* Generated cases are not independent samples, so the intervals are optimistic.
* Mutation rejection rates describe the catalogue in `mutations.mjs`, not all possible attacks.
* Performance figures are single-machine, single-process indications.
